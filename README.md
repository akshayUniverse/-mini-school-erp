# Mini School ERP

A compact school administration app for managing teachers, classes, students, and daily attendance. Administrators manage school data; teachers can view it and mark attendance only for their own classes.

## Live demo

- App: https://mini-school-erp-puce.vercel.app
- Backend: Render free tier, so the first request after inactivity can take ~50 seconds to wake up.
- Login with the demo credentials below.

## Tech stack

- **Node.js + Express 5** — small JSON API with straightforward middleware and routing.
- **MongoDB + Mongoose** — document storage with schema validation, references, timestamps, and unique indexes.
- **JWT + bcryptjs** — bearer-token authentication and password hashing without native build requirements.
- **React + Vite** — component-based single-page UI with a fast development server.
- **React Router + Axios** — role-aware navigation and a shared API client that attaches credentials.
- **Plain CSS** — responsive styling without another UI dependency.

## Setup in under 5 minutes

Requires Node.js 18+ and a running MongoDB instance (local or hosted).

```powershell
git clone <repository-url>
cd <repository-folder>
cd server
npm install
Copy-Item .env.example .env
# Set MONGODB_URI and JWT_SECRET in server/.env if needed
npm run seed
npm run dev
```

In a second terminal:

```powershell
cd <repository-folder>\client
npm install
Copy-Item .env.example .env
npm run dev
```

Open the URL printed by Vite (normally http://localhost:5173). The API runs at http://localhost:5000.

## API

All endpoints return JSON except successful deletes, which return `204 No Content`. Protected endpoints require `Authorization: Bearer <token>`.

| Method | Endpoint | Access | Purpose |
|---|---|---|---|
| POST | `/api/auth/login` | Public | Login with email and password |
| GET / POST / PUT / DELETE | `/api/teachers` (`PUT` and `DELETE` use `/:id`) | Any authenticated user for GET; admin for writes | Manage teachers |
| GET / POST / PUT / DELETE | `/api/classes` (`PUT` and `DELETE` use `/:id`) | Any authenticated user for GET; admin for writes | Manage classes; GET supports `?mine=true` |
| GET / POST / PUT / DELETE | `/api/students` (`PUT` and `DELETE` use `/:id`) | Any authenticated user for GET; admin for writes | Manage students; GET supports `?classId=` and `?search=` |
| POST / GET | `/api/attendance` | Teacher for POST; any authenticated user for GET | Mark today's attendance; filter history by `classId`, `studentId`, `date` |
| GET | `/api/dashboard` | Any authenticated user | School totals and today's attendance per class |

Errors use appropriate `400`, `401`, `403`, `404`, or `409` status codes and a JSON `{ "message": "..." }` body.

## Role permissions

| Capability | Admin | Teacher |
|---|---:|---:|
| View teachers, classes, students, attendance, dashboard | Yes | Yes |
| Create/update/delete teachers, classes, students | Yes | No |
| Mark attendance | No | Yes, for own classes only |
| Filter classes to assigned classes | Yes | Yes |

## Design decisions

- API routes are split by resource; shared authentication, authorization, and error mapping live in middleware.
- Attendance dates are generated by the server in the `Asia/Kolkata` timezone, preventing client clock differences from changing the school day.
- Unique compound indexes enforce class/section, class/roll number, and class/day constraints in the database.
- Attendance saves replace the class's entire set of records for today's date, making repeat submissions an update rather than duplicate entries.
- The client stores only the token and safe user profile in local storage; the API never sends password hashes.
- Teacher access is checked both in the UI and on the server. The server is authoritative.


## Deployment

- **Backend (Render):** root directory `server`, build `npm install`, start `npm start`. Env vars: `MONGODB_URI` (MongoDB Atlas), `JWT_SECRET`, `CLIENT_ORIGIN` (the frontend URL, used for CORS).
- **Frontend (Vercel):** root directory `client`, framework Vite. Env var: `VITE_API_URL` = `<backend-url>/api`. A `vercel.json` rewrite sends all routes to `index.html` so page refreshes work.
